# SPEC — KBM per-keyboard remap

> ステータス: **壁打ち中（実装未着手）**。PLAN.md のユーザー確認事項が未回答のため、方式は未確定。

## 1. 核心の技術的トレードオフ

KBM の remap は `WH_KEYBOARD_LL`（Low-Level Keyboard Hook）で実装されている。
このフックのコールバックは **同期的に「このキーを抑制/書き換えるか」を返す**必要があるが、
イベントに **どの物理デバイス由来かの情報が含まれない**。

一方、物理デバイス識別は **Raw Input（`RegisterRawInputDevices` + `WM_INPUT`）** で可能だが、
Raw Input は**入力を抑制できない**（監視のみ）。しかも `WM_INPUT` はメッセージキュー経由で
LL フックとは**別経路・非同期**に届く。

```
        ┌ 抑制できる ┐        ┌ デバイス識別できる ┐
LL Hook │    ○      │        │        ×         │
Raw Input│   ×      │        │        ○         │
```

→ 「デバイスごとに、元キーを抑制して別キーへ remap」を厳密にやるには、
両方の能力を持つ**フィルタドライバ**（例: [Interception](http://www.oblita.com/interception)）が必要。
これが #1460 が CLOSED（実質保留）になった理由。

## 2. アプローチ候補

| 方式 | デバイス識別 | 抑制 | 実現性 | 備考 |
|---|---|---|---|---|
| A. LL hook のみ（現状） | ✗ | ○ | — | 現行 KBM。デバイス区別不可 |
| B. Raw Input + LL hook 併用（“直近デバイス”ヒューリスティック） | △ | ○ | 中（レースあり） | LL コールバックで「直近に `WM_INPUT` で見えたデバイス」を参照。**同時打鍵・高速切替で誤判定**。単一キーボードで打鍵が交錯しない前提なら実用可能かも |
| C. フィルタドライバ（Interception 等） | ○ | ○ | 低 | 厳密解。だが署名ドライバ配布が必要で Microsoft 受け入れ困難。PowerToys 方針に反する可能性大 |
| D. Raw Input のみ・**抑制なし**（keymap/レイアウト自動切替） | ○ | ✗ | **高** | #12349 相当。打鍵デバイスを検出して「編集対象の keymap セット」や Windows 入力レイアウト/IME を切替。元キー抑制を伴う remap はしない |

## 3. 推奨スコープ（提案）

- **第1段階として方式 D を狙うのが現実的**。
  - `WM_INPUT` で「今アクティブに打鍵しているキーボード」を検出。
  - キーボード → プロファイル（remap セット）の対応表を持ち、アクティブプロファイルを自動切替。
  - “抑制を伴う per-key remap をデバイス単位で”ではなく、“プロファイル（設定一式）をデバイス単位で”切り替える発想。
  - これは #12349（8👍, OPEN）の要望とも一致し、UI も #35632 の「A/B/all ドロップダウン」で素直に表現できる。
- 方式 B は PoC として検証可能だが、レース起因の誤爆リスクを事前に潰す必要あり（要ユーザー合意）。
- 方式 C（ドライバ）は PowerToys 本体としては非現実的。別プロジェクト（ドライバ同梱ツール）として切り出すなら“レポジトリを分ける”判断が初めて意味を持つ。

## 4. 想定コンポーネント（方式 D 前提の暫定）

- Engine 側: Raw Input 受信用の隠しウィンドウ or 既存メッセージループへ `WM_INPUT` 登録。
  デバイスハンドル → デバイス名（`GetRawInputDeviceInfo` / `HidD_GetProductString`）解決。
- 設定: `default.json` にプロファイル概念を追加、またはプロファイルごとに別ファイル。
  デバイス識別子（HID の VID/PID + シリアル等）とプロファイルの対応表。
- Editor(WinUI3/C#): 編集対象プロファイルを選ぶドロップダウン、検出済みキーボード一覧表示。

> 上記は方式が D に確定してから詳細化する。現時点では“候補”に過ぎない。

## 5. 未解決の設計問い
- デバイスの安定した識別子は何にする？（VID/PID はモデル単位、同型2台を区別するにはシリアル/デバイスパスが要る。BT はシリアル取れないことも）
- プロファイル切替の発火条件（1打鍵で即切替？ 一定時間そのデバイスで打鍵継続を確認？）
- 抑制なし方式では“remap 自体はデバイス非依存で全体に効く”ため、ユーザーの真の要望（デバイス別に別 remap）を満たせるか要確認 → PLAN.md 確認事項 #2 に直結。
